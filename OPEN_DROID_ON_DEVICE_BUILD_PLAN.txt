C. EXACT COMMANDS TO INSTALL / FIX MISSING DEPENDENCIES
--------------------------------------------------------------------------------
1. On Debian/Ubuntu/Linux PC:
   sudo apt-get update
   sudo apt-get install -y openjdk-17-jdk git wget unzip cmake
   mkdir -p ~/android-sdk/cmdline-tools
   cd ~/android-sdk/cmdline-tools
   wget https://dl.google.com/android/repository/commandlinetools-linux-11076708_latest.zip
   unzip commandlinetools-linux-11076708_latest.zip
   mv cmdline-tools latest
   export ANDROID_HOME=$HOME/android-sdk
   export PATH=$PATH:$ANDROID_HOME/cmdline-tools/latest/bin:$ANDROID_HOME/platform-tools
   yes | sdkmanager --licenses
   sdkmanager "platforms;android-34" "build-tools;34.0.0" "ndk;26.1.10909125" "cmake;3.22.1" "platform-tools"

2. On Android Device (Termux):
   pkg update && pkg install -y openjdk-17 gradle cmake clang git
   # Or directly open and build using AndroidIDE (which bundles SDK 34, NDK 26, and CMake 3.22)

I. EXACT STEPS TO PLACE GGUF MODEL INTO APP MODEL DIRECTORY
--------------------------------------------------------------------------------
1. Download quantized smoke model:
   wget https://huggingface.co/HuggingFaceTB/SmolLM2-135M-Instruct-GGUF/resolve/main/smollm2-135m-instruct-q4_k_m.gguf -O smollm2-135m-instruct-q4_k_m.gguf

2. Push to target app data directory:
   adb shell "mkdir -p /data/user/0/com.opendroid.app/files/models"
   adb push smollm2-135m-instruct-q4_k_m.gguf /data/local/tmp/model.gguf
   adb shell "run-as com.opendroid.app cp /data/local/tmp/model.gguf /data/user/0/com.opendroid.app/files/models/smollm2-135m-instruct-q4_k_m.gguf"
   adb shell "run-as com.opendroid.app chmod 644 /data/user/0/com.opendroid.app/files/models/smollm2-135m-instruct-q4_k_m.gguf"

N. EXACT SUCCESS / FAILURE CRITERIA FOR EACH TEST
--------------------------------------------------------------------------------
1. Build:
   - Success: libopendroid_llama.so compiled for arm64-v8a and packaged into app-debug.apk without errors.
   - Failure: CMake compilation errors, missing symbols, or linker failure.

2. Model Load:
   - Success: llama_load_model_from_file returns non-null model pointer and memory check passes.
   - Failure: Returns null, logs FILE_NOT_FOUND or INSUFFICIENT_MEMORY.

3. Inference:
   - Success: Output tokens streamed without mock fallback; adheres strictly to GBNF JSON grammar.
   - Failure: GBNF parse exception, unconstrained text, or NativeLlamaCppAdapter crash.

4. Idempotency:
   - Success: Duplicate step execution blocked by Room unique index on UUIDv5 key.
   - Failure: Same tool executes twice with identical parameters.

5. Emergency Stop:
   - Success: Tool execution halted within <100ms; Room updated.
   - Failure: Tool proceeds to mutate Android system state after stop signal.


O. CODE DEFECTS DISCOVERED DURING INSPECTION
--------------------------------------------------------------------------------
1. Runtime Camera Permission Handling:
   - AndroidManifest.xml declares android.permission.CAMERA, but Android 6.0+ requires
     ActivityCompat.requestPermissions at runtime before CameraManager.setTorchMode()
     succeeds on fresh installs.
2. Target Environment Wrapper:
   - gradlew and gradlew.bat shell binaries must be generated via 'gradle wrapper'
     when setting up a new repository clone on the target machine.
3. GGUF Model Download:
   - Model weights must be pushed to device storage via adb before testing inference.
